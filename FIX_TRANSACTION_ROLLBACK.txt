===============================================================
SỬA LỖI: Transaction silently rolled back
===============================================================

## ROOT CAUSE:
1. Class-level @Transactional(noRollbackFor = Exception.class) 
   conflict với nested transactions
2. Khi inventoryService.batchReserveStock() throw exception,
   outer transaction bị mark rollback-only
3. Code catch exception và cố delete order nhưng transaction
   đã rollback → Lỗi "silently rolled back"

## ĐÃ SỬA:

### Fix 1: Xóa class-level @Transactional
File: OrderServiceImpl.java
Line: 58
Before:
  @Transactional(noRollbackFor = Exception.class)
  public class OrderServiceImpl

After:
  public class OrderServiceImpl
  
### Fix 2: Thêm @Transactional vào createOrder()
File: OrderServiceImpl.java  
Line: 129
Before:
  public Order createOrder(...)
  
After:
  @Transactional
  public Order createOrder(...)

### Fix 3: Xóa try-catch và delete trong createOrder()
File: OrderServiceImpl.java
Line: 251-260
Before:
  try {
      inventoryService.batchReserveStock(reservations);
  } catch (Exception e) {
      orderRepository.delete(savedOrder); // ← XÓA DÒNG NÀY
      throw new IllegalStateException(...);
  }

After:
  inventoryService.batchReserveStock(reservations);
  // Transaction tự động rollback nếu có exception

## TẠI SAO SOLUTION NÀY ĐÚNG:

1. Method-level @Transactional với default propagation (REQUIRED)
2. Khi inventoryService.batchReserveStock() fail:
   - Exception được throw ra ngoài
   - Spring tự động rollback TOÀN BỘ transaction
   - Order và Payment đã save sẽ bị rollback
   - KHÔNG CẦN manually delete
3. Frontend nhận exception message rõ ràng: "Không đủ hàng"
